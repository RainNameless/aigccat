# 资产库打包与恢复

在资产库页面点击「打包与恢复」。导出始终包含全库，不受当前搜索、分类和筛选影响。

## 导出和迁移

1. 等待生成、图片处理等任务完成，点击「打包全部资产」。
2. 完成后下载 ZIP。下载结束后可以清理临时文件。
3. 在另一台部署的资产库页面选择该 ZIP，点击「上传并检查备份」。
4. 核对资产、版本、文件数量和重复编号。迁移到空库时保持勾选「恢复备份中的库设置」，才能同时恢复收藏、回收站和项目归属等组织关系。
5. 点击「开始恢复」。服务端写入后会重新读取文件并核对 SHA-256，完成后点击「刷新资产库」。
6. 打开资产，检查图片、模型、历史版本，以及项目文件夹、收藏和回收站。可以再次导出，比较两份清单中的路径、大小和 SHA-256；备份时间可以不同。

备份包含各资产目录下的全部文件：原始参考图、Spec、模型和纹理、版本元数据、历史树和 HEAD、任务记录等。全局部分包括工作台状态、图谱布局、风格设置和消耗汇总。浏览器自定义创作预设可以选择随包迁移。

当前应用同一部署的账号共享资产库，没有账号级数据隔离。因此换账号可以访问该部署的同一份库；跨部署导入则恢复到目标部署的共享库。备份不带服务密钥、登录账号数据库或 Studio 会话，新部署需要单独配置它们。

## 已有资产如何处理

- 默认跳过相同编号，保留目标库中的资产。
- 选择替换时，需要勾选确认；备份会完整替换这些资产的文件和历史，并移除它们在目标库中独有的旧文件。
- 不在备份中的其他资产保持原样。
- 「恢复库设置」会替换全局组织信息，不是合并两个库的文件夹或收藏。目标库已有内容时默认不勾选。

导入预览后若目标库发生变化，恢复会停止，需重新上传并检查。校验失败的包不会写入资产库。恢复中途失败时按持久化日志还原原库；如回滚尚未完成，窗口提供重试入口，服务重启也会尝试恢复。

## 文件和任务限制

使用 aigccat 自己导出的 ZIP，不要重新压缩或修改内容。格式包含 `manifest.json` 和 `objects/`，逐文件记录大小与 SHA-256；只接受当前格式版本、无压缩的普通文件条目，拒绝路径穿越、重复文件、缺失文件和校验不符。JSON 元数据单文件上限 16 MiB。

打包与导入会在服务器临时磁盘暂存文件，需要足够空间容纳 ZIP、解包文件和校验文件；恢复旧库还需要对象存储空间保存回滚副本。文件流式传输，不把整包读进浏览器或服务内存。

关闭窗口不会取消后台打包／恢复，重新打开可查看进度。服务进程重启后需重新上传或打包；已经进入恢复的事务由持久化日志负责回滚。不要把临时下载链接当作长期备份地址。

## 验证

`cargo test` 包含格式往返、校验失败、路径穿越、缺失历史版本与未完成任务拒绝测试。

额外集成测试需要**独立、可丢弃的 MinIO**，固定测试账号为 `backup-test` / `backup-test-password`。设置 `BACKUP_TEST_ENDPOINT` 后运行：

```sh
cargo test library_backup -- --include-ignored --test-threads=1
```

测试会建立随机命名的源库和目标库，检查逐文件恢复、资产列表／详情读取、冲突跳过／替换、失败回滚和启动恢复。不要将此配置指向真实资产存储。
